# REST API

Базовый адрес: `http://127.0.0.1:8000`. JSON кодируется в UTF-8. Для POST и PUT нужен `Content-Type: application/json`. Авторизация отсутствует; API предназначен для локальной доверенной среды.

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/health` | Проверка HTTP-сервера: `{"status":"ok"}` |
| GET | `/api/services` | Сервисы с текущим статусом и статистикой |
| POST | `/api/services` | Создание, `201`, `{"id":1}` |
| GET | `/api/services/1` | Конфигурация сервиса |
| PUT | `/api/services/1` | Полная замена конфигурации |
| DELETE | `/api/services/1` | Удаление вместе с историей |
| POST | `/api/services/1/check` | Запуск проверки, `202` |
| GET | `/api/services/1/history` | Последние проверки и инциденты |
| GET | `/api/report.csv` | Сводный CSV по всем сервисам |

## Создание и изменение

```json
{
  "name": "API магазина",
  "url": "https://example.com/health",
  "category": "Backend",
  "interval": 60,
  "timeout": 5,
  "expected_code": 200,
  "enabled": true
}
```

Обязательны `name` и `url`. Значения по умолчанию: группа «Основные», интервал 60 секунд, таймаут 5 секунд, код 200, проверки включены. PUT использует те же правила: пропущенные необязательные поля принимают значения по умолчанию, это не PATCH.

Ограничения: название до 100 символов, URL до 2000, группа до 50; интервал — целое число 10–86400, таймаут — 1–60, HTTP-код — 100–599. URL должен быть ASCII HTTP(S), без встроенных логина и пароля, пробелов и фрагмента. Для международного домена используйте punycode, для не-ASCII пути — percent encoding. Размер JSON-запроса — до 16 КиБ.

## Параметры списка

```text
GET /api/services?hours=168&q=магазин&status=up&category=Backend
```

- `hours`: период статистики, целое число 1–720, по умолчанию 24.
- `q`: подстрока названия или URL, без учёта регистра.
- `status`: `up`, `down`, `pending`, `paused`; пустое значение отключает фильтр.
- `category`: точное название группы.

Не-ASCII параметры URL нужно кодировать. Фильтры объединяются через AND. Список возвращает конфигурацию и поля `status`, `checked_at`, `response_ms`, `status_code`, `error`, `ok`, `total`, `successful`, `avg_ms`, `uptime`. Без проверок значения последнего результата и `uptime` равны `null`; `total` — 0. `enabled` и `ok` представлены числами 0/1, при записи `enabled` принимается как JSON boolean.

Текущий статус определяется последней проверкой за всё время. Статистика — только выбранным периодом. Фильтры не меняют историю и не передаются в CSV.

## История

`GET /api/services/1/history?hours=24` возвращает объект с массивами `checks` и `incidents`, от новых к старым. До 500 проверок и 100 инцидентов. Открытые инциденты возвращаются независимо от даты начала; закрытые — если пересекались с периодом.

Ручная проверка асинхронна. После `202` результат можно получить обновлением истории. Если проверка этого сервиса уже запущена или стоит в очереди, возвращается `409`. Тело POST для ручной проверки может быть `{}`. Проверка разрешена и для сервиса на паузе.

## CSV

`GET /api/report.csv?hours=168`: UTF-8 с BOM, разделитель `;`, одна строка на сервис. Поля: название, URL, число проверок, число успешных, доступность, средний отклик, период. Если данных нет, процент и средний отклик пустые. Строки, которые могут интерпретироваться как формулы, предваряются апострофом.

## Ошибки

```json
{"error": "Сервис не найден"}
```

`400` — входные данные или период, `403` — чужой Origin при записи, `404` — отсутствующий ресурс или маршрут, `409` — повторная проверка, `415` — неправильный Content-Type, `500` — внутренняя ошибка. Для ручной проверки успешный ответ и `409` содержат поле `message` вместо `error`.
